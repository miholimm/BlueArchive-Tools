# 蔚蓝档案汉化组官网未来规划

> 规划基线：2026-08-14
> 适用范围：官网、管理后台、内容 API、协作工作台和生产部署
> 执行原则：先保证可用与可恢复，再提升运营效率，最后扩展社区能力。

## 一、现状与边界

当前系统已具备官网展示、公告、下载、九项维护状态、教程、FAQ、反作弊追踪、反馈处理、术语库、问答、协作任务、组员权限、模块可见性、审计日志和 API Key 管理能力。前端采用 React、TypeScript、Vite 与 TailwindCSS，服务端采用 Express；运行内容默认存放在 JSON 文件中，并支持将部分站点内容迁移至 PostgreSQL。

未来迭代不改变以下边界：

- 协作工作台和历史归档始终只对管理员开放。
- 国服汉化支持不再恢复为站点功能或状态项。
- 管理员密码、组员密码摘要、API Key、会话、访客记录和线上运行数据不进入公开仓库。
- 状态页继续以管理员维护的资源版本比对和强制状态为准，不在前后台展示自动判定规则说明。
- 任何发布均不得覆盖生产环境的 `.env`、共享数据目录或既有账号数据。

## 二、优先级和成功标准

| 优先级 | 目标 | 完成标准 |
| --- | --- | --- |
| P0 | 稳定上线与可恢复 | HTTPS 正常、备份可恢复、核心 API 和后台回归通过 |
| P1 | 降低运营成本 | 内容发布、状态维护、权限管理和反馈闭环可由管理员独立完成 |
| P2 | 提升协作效率 | 任务、术语、审核和通知形成可追踪工作流 |
| P3 | 扩展社区与生态 | 对外 API、社区互动和数据分析在安全边界内稳定运行 |

每个阶段开始前明确负责人、预计完成日和回滚方案；每个阶段结束后记录验收结果、遗留风险和下一阶段输入。

## 三、阶段 0：上线收尾与基线固化

**目标周期：立即执行，完成后才进入功能扩展。**

### 交付项

1. 完成新域名的 HTTPS 上线。
   - 修复 ACME 验证链路后签发证书。
   - HTTP 统一 301 跳转至 HTTPS。
   - 验证首页、`/admin`、`/api/content`、QQ OAuth 回调地址和证书自动续期。
   - 保留旧站作为短期回退入口，确认稳定后再设定下线窗口。

2. 固化发布和回滚流程。
   - 发布包仅包含构建产物、服务端代码、公开种子数据和依赖清单。
   - 采用版本目录加 `current` 软链接发布，发布前创建可验证的运行数据备份。
   - 建立“发布前构建、API 回归、人工后台巡检、线上健康检查”的固定清单。

3. 建立备份与恢复演练。
   - 每日备份共享 JSON 数据和可选 PostgreSQL 数据库。
   - 将至少一份加密备份存放在不同于生产服务器的位置。
   - 每月在隔离目录演练一次恢复，确认账号、权限、公告、术语、任务和状态数据可读。

4. 固化代码治理。
   - 将不含隐私信息的源码推送至组织仓库。
   - 配置受保护分支、拉取请求审查和 CI。
   - CI 至少执行 `pnpm install --frozen-lockfile`、`pnpm run build` 和 `pnpm run test:api`。

### 验收标准

- 新域名只能通过有效 HTTPS 访问，证书续期演练成功。
- `blue-archive-hh.service`、Nginx 和 Certbot 定时器均处于活动状态。
- 发布后 `settings.backgroundDim` 和九项资源状态完整保留。
- 从备份恢复到隔离环境后，核心 API 回归脚本通过。

## 四、阶段 1：后台运营能力完善

**目标周期：上线稳定后的 2 至 4 周。**

### 内容工作流

- 为公告、下载资源、教程、FAQ 和反作弊追踪加入草稿、预览、定时发布和修订记录。
- 为每次内容变更记录操作者、变更时间、变更摘要和可回退版本。
- 增加下载链接的上线前校验，包括 HTTPS、文件大小、校验值格式和失效链接提示。
- 为维护状态编辑器增加批量更新时间、版本复制和缺失字段提示，减少人工录入错误。

### 管理与权限

- 将组员权限从模块级扩展为“查看、创建、编辑、审核、发布”五类动作权限。
- 增加角色模板，例如内容编辑、状态维护、术语审核、社区审核和安全审计员。
- 增加账号最后登录时间、会话列表、强制下线、密码重置通知和禁用原因记录。
- 为高风险操作增加二次确认和审计日志，例如删除账号、撤销 API Key、改变游客可见性和批量删除内容。
- 评估并实施主管理员双因素认证；在启用前先确认恢复码和应急登录流程。

### 运营通知

- 反馈被采纳、回复或拒绝时提供站内状态更新和可选通知。
- 公告发布、任务待审核、资源状态异常和备份失败产生管理员通知。
- 将 Discord Webhook 设计为可选能力，支持测试消息、失败重试和禁用开关，不在公开接口返回 Webhook 地址。

### 验收标准

- 无需直接修改服务器文件即可完成日常内容更新。
- 低权限组员无法通过接口绕过后台菜单限制。
- 任一后台变更可在审计日志中定位到账号、时间和影响对象。

## 五、阶段 2：汉化协作工作流

**目标周期：阶段 1 完成后的 1 至 2 个月。**

### 任务协作

- 为任务增加优先级、标签、依赖关系、预计工作量、审核人和截止时间。
- 支持任务从待认领、进行中、待审核、已退回到已完成的标准流转。
- 支持提交翻译文本、附件链接和审核意见；敏感附件使用受控对象存储而非服务器本地目录。
- 提供任务看板、个人待办、逾期提醒和周度进度汇总。

### 术语与质量

- 将术语库改为“提案、审核、发布”流程，保留原词、译词、上下文、出处和修改历史。
- 建立术语冲突提示和搜索同义词功能，避免同一角色、地点或技能出现多种译法。
- 为翻译提交增加基础格式检查，例如占位符、换行、标签、特殊字符和长度风险。
- 定义抽样校对规则和严重问题等级，以便从反馈、任务和公告中汇总质量趋势。

### 验收标准

- 每个已完成任务可追溯到提交者、审核者、关联术语和最终版本。
- 术语修改不会直接覆盖既有发布版本，必须经过审核记录。
- 管理员可在一个页面查看当前积压、逾期和待审核任务。

## 六、阶段 3：数据、性能与可观测性

**目标周期：阶段 2 稳定后，按流量和协作规模决定。**

### 数据演进

- 保持 JSON 作为小规模部署的零配置方案，同时完成高并发数据的 PostgreSQL 迁移设计。
- 优先迁移公告、反馈、评论、任务、术语、问答、审计日志和访客记录。
- 采用“备份、只读校验、双写验证、切换、回滚窗口”的分步迁移，不一次性替换全部存储。
- 为数据增加模式版本和迁移脚本，避免新版本读取旧数据时出现静默丢失。

### 性能优化

- 对管理后台、剧情阅读器、API 文档和问答等低频页面实施路由级懒加载。
- 为公告、术语和问答加入服务端分页、缓存头和查询限制。
- 优化图片格式、尺寸和懒加载策略，明确封面图与壁纸的文件大小预算。
- 使用真实设备和弱网环境评测桌面、平板和移动端的加载与交互体验。

### 可观测性

- 建立服务健康检查、错误率、响应时间、证书到期、磁盘空间和备份结果监控。
- 将应用错误日志与访问日志按保留周期归档，避免无限增长。
- 对隐私数据进行最小化采集：访客 IP、User-Agent 和反馈原文仅保留运营所需时间。
- 设定告警分级和响应人，避免出现异常但无人知晓的情况。

### 建议指标

| 指标 | 初始目标 |
| --- | --- |
| 公开页面成功率 | 30 天内不低于 99.5% |
| 核心 API P95 响应时间 | 不高于 500ms |
| 公告与状态更新可见时间 | 保存后 1 分钟内 |
| 严重反馈首次响应 | 2 个工作日内 |
| 备份恢复演练 | 每月 1 次 |
| 发布回归通过率 | 100% |

## 七、阶段 4：社区与开放生态

**目标周期：基础稳定且有明确维护人力后再启动。**

- 为问答和评论引入可选的可信身份体系，保留匿名浏览，避免将后台权限与社区身份混用。
- 完善内容举报、反垃圾、敏感词审核、冻结和申诉流程。
- 对外 API 采用明确的版本、配额、弃用策略和隐私说明，API Key 只授予必要范围。
- 提供可订阅的更新源，例如 RSS、Webhook 或公开状态订阅，避免依赖爬虫。
- 评估 PWA、离线阅读和多语言站点，但不以牺牲加载速度、版权合规和维护成本为代价。

## 八、持续质量机制

每次发布都执行以下流程：

1. 新功能先补充 API 回归用例和关键页面人工验收项。
2. 本地执行依赖安装、生产构建和 API 回归。
3. 在独立端口或预发布环境验证，不直接覆盖运行中的生产目录。
4. 发布前备份数据，发布后检查首页、下载、维护状态、反馈、FAQ、术语库、工作台和全部后台标签。
5. 观察日志与关键指标，确认无异常后关闭发布窗口。
6. 如出现账号、数据、权限或可用性问题，优先回滚并保留现场，再分析根因。

## 十、需要管理员确认的决策

- 新域名的 DNS 托管方和公网防火墙控制权，以便解决证书签发链路。
- 备份保存期限、离机存储位置和可访问的管理员名单。
- 各类组员角色的实际职责边界，以及是否启用双因素认证。
- 是否需要对公告、下载、教程和 FAQ 启用定时发布。
- 何时将高频协作数据从 JSON 迁移到 PostgreSQL。

在这些决策未明确前，优先完成 P0 项目，不把未经授权的第三方接口抓取、自动发布、公开协作数据或不可逆的数据迁移纳入上线范围。
