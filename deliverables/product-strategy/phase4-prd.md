### 原始需求复述

阶段四定位从"单一汉化组网站"升级为"汉化生态平台"。核心能力：开放 API 供第三方工具集成（配合防抓包需求），建设汉化协作工作台让外部贡献者参与翻译，探索社区建设（Discord、QA 板块）和生态合作（威威字幕君、多游戏扩展）。

---

## 2. 产品定义

### 2.1 产品目标

1. **平台化开放** — 通过签名验证的开放 API，让第三方工具（翻译辅助工具、Discord Bot、玩家客户端）可安全查询汉化状态，使网站从"展示面"变成"数据中心"。
2. **协作降槛** — 建设翻译协作工作台，使外部贡献者无需加入内部群即可认领任务、使用术语库、追踪进度，降低参与门槛。
3. **社区自运转** — 通过 QA 互助板块和 Discord 桥梁，让用户帮助用户，减少核心成员在重复问题上的精力消耗。

## 3. 技术规范

### 3.1 需求池与优先级

#### P0 — 必须在阶段四完成（无。本阶段无 P0 关键路径阻塞项）

#### P1 — 核心交付（前 3 个月，2027.01 - 2027.04）

| ID | 需求 | 验收标准 |
|---|---|---|
| **R4.1** | **开放 API — 汉化状态查询** | (1) `GET /api/v1/status` 返回各章节翻译进度 JSON；(2) 支持 `?chapter=` 筛选；(3) 响应时间 < 50ms；(4) 提供 Swagger/OpenAPI 文档页面 `/api/docs` |
| **R4.2** | **API Key 管理后台** | (1) 管理后台新增「API 管理」Tab；(2) 支持创建/吊销 Key、设置备注和速率限额；(3) Key 以 `ba_` 前缀展示，完整值仅创建时可见 |
| **R4.3** | **HMAC-SHA256 签名验证** | (1) 请求头携带 `X-BA-Timestamp`、`X-BA-Signature`；(2) 签名 = HMAC-SHA256(timestamp + method + path + body, secretKey)；(3) 时间戳偏差超过 5 分钟的请求拒绝；(4) 签名错误返回 401 |
| **R4.4** | **速率限制** | (1) 默认每 Key 100 次/分钟、1000 次/小时；(2) 超限返回 429 + Retry-After 头；(3) 管理后台可配置限额 |

#### P2 — 中期交付（中 2 个月，2027.04 - 2027.06）

| ID | 需求 | 验收标准 |
|---|---|---|
| **R4.5** | **任务池与认领** | (1) 新增 `/workspace` 路由展示任务列表；(2) 贡献者可按章节认领（需先填写昵称+联系方式）；(3) 同一任务同一时间仅一人认领；(4) 72 小时未提交自动释放 |
| **R4.6** | **进度追踪面板** | (1) 管理后台展示所有任务状态（待认领/进行中/待审核/已完成）；(2) 支持按章节/状态/贡献者筛选；(3) 进度百分比可视化 |
| **R4.7** | **术语库共享** | (1) 新增 `/glossary` 路由，公开只读；(2) 支持搜索（中文/日文/罗马音）；(3) 管理后台可编辑术语条目；(4) 数据格式：`{ ja, zh, romaji, category, note }` |

#### P3 — 体验优化与探索（后 2 个月，2027.06 - 2027.08）

| ID | 需求 | 验收标准 |
|---|---|---|
| **R4.8** | **社区 QA 板块** | (1) 新增 `/qa` 路由；(2) 支持提问/回答/点赞/采纳；(3) 按标签分类（安装/翻译/技术/其他）；(4) 敏感词过滤 + 管理员审核队列 |
| **R4.9** | **Discord 社区搭建** | (1) 创建 Discord 服务器并配置频道结构；(2) Webhook 自动推送公告和状态变更到 Discord；(3) 官网页脚新增 Discord 入口 |
| **R4.10** | **威威字幕君合作** | 完成合作对接文档（技术方案 + 内容授权），评估是否可复用 API 接口 |
| **R4.11** | **多游戏汉化扩展评估** | 输出评估报告：候选游戏列表（≥3）、资源需求估算、ROI 预估、技术复用度分析 |

### 3.2 UI 设计草案

#### 新增路由（预计 +5~6 条，总数达 22~23 条）

| 路由 | 页面 | 优先级 |
|---|---|---|
| `/api-docs` | API 文档页（Swagger UI 嵌入） | P1 |
| `/workspace` | 翻译协作工作台（任务列表 + 认领） | P2 |
| `/workspace/:taskId` | 任务详情 + 提交翻译 | P2 |
| `/glossary` | 术语库（公开只读 + 搜索） | P2 |
| `/qa` | 社区问答板块 | P3 |
| `/admin/api-keys` | API Key 管理（管理后台新 Tab） | P1 |

#### Navbar 调整

当前 10 项导航，阶段四新增 **2 项公开入口**：「协作台」和「问答」，**1 项**根据情况定（术语库可放在协作台子页面或用 footer 链接）。

建议 Navbar 结构（共 12 项，控制在合理范围）：
`首页 | 剧情库 | 汉化状态 | 公告 | 资源下载 | 协作台 | 问答 | 教程 | 成员 | 更新日志 | API`

#### 关键 UI 说明

- **API 文档页**：嵌入 Swagger UI 静态资源，保持液态玻璃主题风格统一
- **协作工作台**：类 Kanban 或表格式任务列表，状态标签色区分
- **术语库**：三列搜索布局（日文/中文/备注），响应式表格
- **QA 板块**：参考 Stack Overflow 简洁风格，右侧标签分类

### 3.3 数据存储扩展

新增 JSON 文件：

| 文件 | 用途 |
|---|---|
| `server/data/api_keys.json` | API Key 存储（key_hash, name, rate_limit, created_at, revoked） |
| `server/data/tasks.json` | 翻译任务（chapter, status, claimant, submitted_at, reviewed_at） |
| `server/data/glossary.json` | 术语条目 |
| `server/data/qa.json` | QA 问答数据 |

### 3.4 安全设计要点

- API Key 存储使用 SHA-256 哈希，不存明文
- 签名验证中间件独立封装，可复用于未来所有 API 端点
- 速率限制使用内存计数器（当前架构无 Redis），服务重启后重置（可接受）
- QA 板块复用现有评论系统的敏感词过滤机制
